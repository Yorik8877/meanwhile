# Секундомер задач: дизайн

Дата: 2026-10-14
Статус: на ревью

## 1. Назначение

Личный учёт времени по задачам, которые выполняются параллельно. Цель — видеть,
сколько реально уходит на каждую задачу, сегодня и за всё время, с разбивкой
по дням. Отчёты, выгрузка и синхронизация не нужны.

Критерии успеха:

- Несколько задач можно запускать и ставить на паузу независимо друг от друга.
- Время не теряется и не накручивается при перезапуске программы, сне компьютера
  и аварийном завершении (погрешность при аварии — не больше 1 минуты).
- Ошибочно учтённое время можно исправить, отредактировав отрезки работы.
- Программа ставится одним бинарником, живёт в трее и запускается при входе
  в систему.

## 2. Объём первой версии

Входит:

- задачи с названием и заметкой: создание, изменение, удаление;
- независимые таймеры по задачам, пауза для всех;
- время задачи за сегодня и за всё время, история по дням (по неделям);
- редактор отрезков: изменение, добавление, удаление;
- иконка в трее с двумя состояниями и меню;
- пауза всех таймеров при сне, выключении компьютера и выходе из программы;
- восстановление после аварийного завершения;
- защита от запуска второго экземпляра;
- интерфейс на русском и английском;
- установка и удаление через Makefile без sudo.

Не входит:

- выгрузка и отчёты;
- проекты, теги, архив задач;
- переключатель языка в настройках;
- собственная тема оформления (используется стандартная тема Fyne);
- обнаружение сна без logind/elogind (сравнение настенных и монотонных часов) —
  интерфейс для него закладывается, реализация откладывается;
- пакеты дистрибутивов (.deb и т. п.), сборка под Windows и macOS.

## 3. Платформа и стек

- ОС: Linux, любой дистрибутив, X11 или Wayland (через XWayland).
- Язык: Go (сборка проверена на Go 1.27).
- GUI и трей: Fyne v2.8.x (`fyne.io/fyne/v2`). Трей через
  `desktop.App.SetSystemTrayWindow` (Fyne ≥ 2.7): левый клик показывает окно,
  правый — меню.
- База данных: SQLite через `modernc.org/sqlite` (чистый Go, без системной
  libsqlite).
- D-Bus: `github.com/godbus/dbus/v5`, только для системной шины
  (`org.freedesktop.login1`).
- Сигналы о сне и выключении: интерфейс `login1`, который предоставляет
  systemd-logind или elogind. Код для них общий.

Сборке нужны Go, компилятор C и заголовки OpenGL и X11 (CGO обязателен для Fyne).
Если libc целевой системы отличается от системы сборки (glibc и musl),
собирать нужно на целевой системе.

## 4. Архитектура

```text
cmd/stopwatch/        точка входа: разбор флагов, создание и связывание компонентов
internal/tracking/    предметная область: задачи, отрезки, подсчёт времени
internal/storage/     реализация хранилища на SQLite
internal/power/       сигналы о сне и выключении от login1
internal/instance/    единственный экземпляр: файл-замок и Unix-сокет
internal/ui/          окно, вкладки, редактор отрезков, трей, иконки, переводы
```

Направление зависимостей: `cmd` → все; `ui`, `storage`, `power` → `tracking`;
`tracking` не зависит ни от кого из перечисленных, ни от Fyne, ни от SQLite.

### 4.1. tracking

Сервис `Tracker` — единственная точка изменения данных. Операции:

- `CreateTask(name, note)`, `UpdateTask(id, name, note)`, `DeleteTask(id)`;
- `Start(taskID)`, `Pause(taskID)`, `PauseAll(at)`;
- `AddInterval(taskID, start, end)`, `UpdateInterval(id, start, end)`,
  `DeleteInterval(id)`;
- запросы: список задач с временем за сегодня и за всё время, отрезки задачи,
  время по дням за период, задачи для меню трея;
- `RecoverAfterCrash()` и `RecordHeartbeat()` (см. 6.5).

`tracking` объявляет нужные ему интерфейсы:

- `Repository` — чтение и запись задач, отрезков и служебных значений;
- `Clock` — текущее время (в тестах подменяется).

Каждая изменяющая операция сначала записывает изменение через `Repository`
и только после успешной записи обновляет состояние в памяти и уведомляет
подписчиков. Подписчики (окно и меню трея) перерисовываются по уведомлению.

Ошибки предметной области — типизированные значения (`ErrEmptyName`,
`ErrEndBeforeStart`, `ErrIntervalInFuture`, `ErrIntervalsOverlap`,
`ErrRunningIntervalEnd` и т. п.), без готового текста. Текст на нужном языке
подбирает `ui`.

### 4.2. storage

Реализует `tracking.Repository` поверх SQLite. При открытии создаёт или
обновляет схему (версия в `PRAGMA user_version`), включает
`PRAGMA foreign_keys = ON` и режим журнала WAL.

### 4.3. power

Подключается к системной шине и подписывается на сигналы `login1`:

- `PrepareForSleep(true)` → `PauseAll(момент сигнала)`, затем снимает задержку;
- `PrepareForSleep(false)` (пробуждение) → снова берёт задержку сна;
- `PrepareForShutdown(true)` → `PauseAll(момент сигнала)`, снимает задержку.

Задержка — inhibitor-блокировка `login1` в режиме `delay` на `sleep` и
`shutdown`: она даёт программе время записать паузу до засыпания.

Если `login1` на шине нет, `power` пишет предупреждение в лог и ничего
не делает. Остальная программа работает; таймеры во сне не останавливаются.

`power` скрыт за интерфейсом, чтобы позже добавить обнаружение сна
сравнением часов без изменения остального кода.

### 4.4. instance

1. При запуске берёт эксклюзивную блокировку `flock` на файл
   `<runtime-dir>/stopwatch.lock`.
2. Получив блокировку, слушает Unix-сокет `<runtime-dir>/stopwatch.sock`
   (старый файл сокета перед этим удаляется).
3. Не получив блокировку, подключается к сокету, отправляет команду `show`
   и завершает процесс с кодом 0.

Команда `show` показывает окно в работающем экземпляре. Ядро снимает `flock`
при завершении процесса, в том числе аварийном, поэтому зависших замков нет.

`<runtime-dir>` — `$XDG_RUNTIME_DIR`, а если переменная не задана —
папка состояния (см. раздел 9).

Путь к Unix-сокету в Linux ограничен 107 байтами. Если путь длиннее
(например, при глубокой папке `--data-dir`), используется абстрактный сокет
Linux с именем `stopwatch.sock-<хэш пути>`: у него нет файла и нет ограничения
на длину пути к папке.

### 4.5. ui

Отображает данные `Tracker` и передаёт ему действия пользователя. Раз в секунду
обновляет показ тикающих таймеров; все изменения интерфейса из горутин
выполняются через `fyne.Do`.

## 5. Модель данных

Все моменты времени хранятся как целые миллисекунды Unix (UTC).

`tasks`:

| Поле | Тип | Ограничения |
| --- | --- | --- |
| `id` | INTEGER | первичный ключ |
| `name` | TEXT | NOT NULL, не пустое после обрезки пробелов (проверяет `tracking`) |
| `note` | TEXT | NOT NULL, по умолчанию `''` |
| `created_at` | INTEGER | NOT NULL |

`intervals`:

| Поле | Тип | Ограничения |
| --- | --- | --- |
| `id` | INTEGER | первичный ключ |
| `task_id` | INTEGER | NOT NULL, ссылка на `tasks.id`, `ON DELETE CASCADE` |
| `started_at` | INTEGER | NOT NULL |
| `stopped_at` | INTEGER | NULL — отрезок идёт сейчас; `CHECK (stopped_at IS NULL OR stopped_at >= started_at)` |

Индексы: по `task_id`; частичный уникальный индекс по `task_id`
`WHERE stopped_at IS NULL` — у задачи не больше одного открытого отрезка.

`app_state`: `key TEXT PRIMARY KEY`, `value TEXT NOT NULL`. Ключи:
`last_heartbeat_at` — миллисекунды Unix.

Задача «идёт», если у неё есть открытый отрезок.

## 6. Поведение

### 6.1. Подсчёт времени

- Время задачи — сумма длительностей её отрезков. Открытый отрезок считается
  до текущего момента.
- Разбивка по дням: отрезок делится по местной полуночи. Полночь вычисляется
  календарно (`time.Date` в местном часовом поясе), поэтому сутки по 23 и 25 часов
  при переходе на летнее время учитываются верно.
- «Сегодня» — часть отрезков, попавшая в текущие местные сутки. Смена суток
  подхватывается при ближайшем ежесекундном обновлении.
- Итог дня в истории — сумма времени задач за день. При параллельной работе
  он может превышать прошедшее время; интерфейс об этом сообщает.

### 6.2. Задачи

- Название обязательно, обрезается по краям, повторы допустимы.
- Заметка — многострочный текст, может быть пустой.
- Удаление задачи требует подтверждения и удаляет все её отрезки.
- Задачу можно удалить, даже если она идёт.

### 6.3. Таймеры

- `Start` открывает новый отрезок с текущим моментом. Повторный `Start` у идущей
  задачи ничего не делает.
- `Pause` закрывает открытый отрезок текущим моментом. Если текущий момент
  раньше начала отрезка (часы перевели назад), отрезок закрывается своим началом.
- `PauseAll(at)` закрывает все открытые отрезки моментом `at` по тому же правилу.
- После сна, перезапуска или восстановления таймеры сами не возобновляются.

### 6.4. Редактирование отрезков

Правила (нарушение — типизированная ошибка, изменение не сохраняется):

- начало строго раньше конца;
- конец не позже текущего момента;
- отрезок не пересекается с другими отрезками той же задачи; открытый отрезок
  при проверке считается до текущего момента;
- у открытого отрезка можно менять только начало, и оно не позже текущего момента;
- отрезки разных задач пересекаться могут.

Время в форме вводится с точностью до минуты (`ЧЧ:ММ`), у изменённого поля
секунды обнуляются, у неизменённого — сохраняются.

### 6.5. Завершение и восстановление

- Штатный выход (пункт «Выход», `SIGTERM`, `SIGINT`, завершение сеанса) вызывает
  `PauseAll` и закрывает базу.
- Раз в 60 секунд `RecordHeartbeat` записывает текущий момент
  в `last_heartbeat_at`.
- При запуске `RecoverAfterCrash` закрывает все открытые отрезки моментом
  `max(started_at, last_heartbeat_at)`. Если отметки нет, отрезок закрывается
  своим началом.

## 7. Интерфейс

### 7.1. Главное окно

Обычное окно с рамкой. Крестик прячет окно в трей, таймеры продолжают идти.
Две вкладки: «Задачи» и «История».

Вкладка «Задачи»:

- сверху поле «Новая задача» и кнопка «Добавить» (Enter тоже добавляет);
- список задач, новые сверху; порядок не меняется при старте и паузе;
- строка задачи: кнопка ▶/⏸; название; первая строка заметки серым, если есть;
  время за сегодня и всего в формате `Ч:ММ:СС`; кнопка «⋯» с пунктами
  «Изменить», «Отрезки», «Удалить»;
- идущая задача выделена, её время тикает каждую секунду;
- внизу кнопка «Пауза для всех», неактивна, когда ничего не идёт.

Вкладка «История»:

- переключатель недель «← неделя» / «неделя →», неделя с понедельника;
- дни недели от свежих к старым; у дня итог и под ним задачи с временем
  за этот день; задачи без времени в этот день не показываются;
- подсказка, что при параллельной работе итог дня может превышать прошедшее время.

### 7.2. Редактор отрезков

Диалог для одной задачи:

- список отрезков, свежие сверху: дата, начало–конец, длительность,
  кнопки «Изменить» и «Удалить» (удаление с подтверждением);
- кнопка «Добавить отрезок»;
- форма: дата и время начала, дата и время конца; у открытого отрезка поля
  конца недоступны;
- при нарушении правил из 6.4 форма не закрывается и показывает понятную ошибку.

### 7.3. Трей

- Иконка двух видов: «всё на паузе» и «хотя бы один таймер идёт».
- Левый клик показывает окно.
- Меню по правому клику:
  - «Открыть»;
  - разделитель;
  - задачи с галочкой (галочка — идёт), клик переключает старт/пауза;
    показываются все идущие задачи, затем недавно активные (по последнему
    `started_at`, а без отрезков — по `created_at`), всего не больше 10;
    если идущих больше 10, показываются все идущие;
  - разделитель;
  - «Пауза для всех» (неактивна, когда ничего не идёт);
  - «Выход».
- Время в меню не показывается: не все рабочие столы обновляют открытое меню.
- Меню и иконка обновляются по уведомлениям `Tracker`.

### 7.4. Языки

- Русский и английский, переводы в `en.json` и `ru.json`, встроены в бинарник,
  загружаются через пакет Fyne `lang`.
- Язык выбирается по системной локали (`LANGUAGE`, `LC_ALL`, `LANG`);
  если ни русский, ни английский не подходят — английский.
- Названия дней недели и месяцев берутся из файлов переводов.

## 8. Обработка ошибок

| Ситуация | Поведение |
| --- | --- |
| База не открывается при запуске | Окно с текстом ошибки и путём к файлу, затем выход с ненулевым кодом |
| Ошибка записи в базу во время работы | Изменение не применяется, показывается окно ошибки, программа работает дальше |
| Нет `login1` на системной шине или нет системной шины | Предупреждение в лог; таймеры во сне не останавливаются |
| Не удалось создать замок или сокет | Ошибка в лог, программа работает без защиты от второго экземпляра |
| Трей недоступен | Ручной запуск всегда показывает окно (см. раздел 9), повторный запуск показывает окно работающего экземпляра |
| Часы переведены назад | Отрезки закрываются не раньше своего начала, отрицательных длительностей нет |

## 9. Файлы и запуск

| Что | Путь по умолчанию | Переменная XDG |
| --- | --- | --- |
| База | `~/.local/share/stopwatch/stopwatch.db` (+ `-wal`, `-shm`) | `XDG_DATA_HOME` |
| Лог | `~/.local/state/stopwatch/stopwatch.log` | `XDG_STATE_HOME` |
| Замок и сокет | `$XDG_RUNTIME_DIR/stopwatch.{lock,sock}` | `XDG_RUNTIME_DIR` |

Флаги:

- `--hidden` — не показывать окно при запуске (используется автозапуском);
- `--data-dir <папка>` — хранить базу, лог, замок и сокет в указанной папке
  (для разработки: отладочная копия не мешает установленной).

Лог пишется через `log/slog`.

## 10. Сборка и установка

| Команда | Действие |
| --- | --- |
| `make build` | собирает `bin/stopwatch` |
| `make test` | запускает тесты |
| `make install` | копирует бинарник в `$(PREFIX)/bin`, `.desktop`-файл в `~/.local/share/applications/`, иконку `io.github.stopwatch.svg` в `~/.local/share/icons/hicolor/scalable/apps/`, `.desktop`-файл автозапуска с `--hidden` в `~/.config/autostart/` |
| `make uninstall` | удаляет установленные файлы, данные не трогает |
| `make uninstall PURGE=1` | дополнительно спрашивает подтверждение `[y/N]` и удаляет папки данных и логов; без терминала ответ считается «нет» |

`PREFIX` по умолчанию — `~/.local`. Перед удалением `make uninstall`
проверяет, не запущена ли программа (подключением к сокету экземпляра),
и если запущена — останавливается с просьбой выйти из программы.

## 11. Тестирование

- `tracking`: модульные тесты с подменёнными часами и хранилищем в памяти.
  Старт и пауза, параллельные задачи, пауза для всех, разбивка через полночь,
  сутки перехода на летнее время (`Europe/Berlin`), все правила 6.4,
  восстановление после сбоя, часы назад.
- `storage`: тесты на настоящей SQLite во временной папке: создание схемы,
  запрет второго открытого отрезка, каскадное удаление, сохранность данных
  между открытиями.
- `instance`: тест на двух экземплярах в одном процессе с временной папкой:
  второй получает отказ и доставляет `show` первому.
- Переводы: тест на совпадение набора ключей в `en.json` и `ru.json`.
- `ui`: несколько тестов через `fyne.io/fyne/v2/test` (добавление задачи,
  старт/пауза из списка).
- Вручную: трей, сон (`systemctl suspend`), выключение, автозапуск,
  `make install` / `make uninstall`.

## 12. Допущения, принятые без отдельного обсуждения

- Имя Go-модуля — `stopwatch`; его легко сменить позже.
- После сна и перезапуска таймеры не возобновляются автоматически.
- Неделя в истории начинается с понедельника для обоих языков.
- Повторяющиеся названия задач допустимы.
- Иконки (приложения и двух состояний трея) рисуются в SVG в рамках проекта.
